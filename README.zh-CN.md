# ChatGPT / Codex 项目无法用于本地聊天：Windows 规避方案

[English](README.md) · [配置步骤](docs/SETUP.md) · [其他人的报告与链接](docs/REFERENCES.md) · [如何验证](docs/VERIFICATION.md)

面向以下错误：**“无法将此项目用于本地聊天”**，英文 **“Could not use this project for a local chat”**。

**这是社区规避方案，不是 OpenAI 官方永久修复。** 本仓库记录 2026-10-03 在一台 Windows 电脑上的排查和恢复，提供原创启动器代码；个人目录、项目名称、项目 ID、登录文件和原始日志均未公开。

## 一、问题怎么出现

- 在 ChatGPT 云项目中使用 Chat 可以对话。
- 在同一个项目中创建本地 Work，或把 Chat 切换成 Work，出现上述错误。
- 有时还提示“Could not sync ChatGPT project context”。
- 已有 Work 或项目外的 Work 可能仍可用。
- 多个项目、多台电脑可能出现类似现象，但同一句错误也可能来自不同失败原因。

## 二、本次排查发现什么

当前安装的同步实现会准备临时副本，再对整个已有项目副本改名并替换。浏览器工具与其解释器子进程却把这个副本当作工作目录，持有目录句柄。对目标目录申请访问权限但不执行删除时，Windows 返回 **32：共享冲突**。

第一次规避设置把 `node_repl` 移到了固定目录，并修改了浏览器插件缓存中的 `cwd`。完整重启后，解释器的共享设置仍生效，但应用重建浏览器插件清单，清掉了 `cwd`。浏览器工具又回到项目副本中，普通输入框继续失败。

本机没有在桌面日志中捕获具体失败改名操作的系统错误码；目录占用、共享冲突和恢复后的进程状态支持这一机制。不能仅凭 `stage=filesystem` 就把所有同类提示都认定为文件锁。

相关公开报告：[目录被占用 #46898](https://github.com/openai/codex/issues/46898)、[缓存中的修复配置反复失效 #48534](https://github.com/openai/codex/issues/48534)。这些是报告者的观察，不应全部写成官方确认的统一根因。

## 三、最终采用的方式

1. 把 `node_repl` 的固定工作目录设置放到各项目副本之外的共享配置层。
2. 增加根标记和限定到副本父目录的信任，让应用能够发现共享配置。
3. 验证当前版本允许完整用户 MCP 配置接管同名 `cua_repl` 浏览器工具，然后设置固定目录启动器。
4. 启动器每次从内置插件清单读取应用新生成的工具命令、参数和环境，保持原工具运行，从固定目录启动整个工具进程链。
5. 沿用现有工具策略，保留插件安装状态。

具体操作见 [SETUP.md](docs/SETUP.md)。不要把别人的用户名、运行时路径或整份配置直接复制过来。仓库不提供自动修改配置、结束进程或清空缓存的安装脚本。

普通 MCP 的命令、工作目录等参数见[官方配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)。完整用户配置接管同名插件服务器的行为在本次版本中实际验证过，仍需在其他版本检查。

## 四、实际验证范围

本次应用显示版本 **26.930.31730**，build **12947**；Store 包版本 **26.930.3930.0**。

| 项目 | 结果 |
| --- | --- |
| 六个云项目的目标路径读取共享设置 | 全部通过 |
| 插件缓存未设置工作目录时，实际服务器列表仍读取新目录 | 通过 |
| 独立启动浏览器工具并读取工具列表 | 通过 |
| 启动器、浏览器工具、解释器子进程使用固定目录 | 通过 |
| 一个现有项目的普通 Work 输入框 | 用户确认成功 |
| 新任务实际工具进程离开项目副本 | 确认 |
| 其他五个项目逐个界面测试 | 尚未完成 |
| 最终配置下再次完整重启复测 | 尚未完成 |
| 另一台电脑、其他系统和后续更新 | 尚未验证 |

一个项目尚未生成本地副本，但其目标路径能够读取共享配置；没有创建空副本来冒充恢复。

旧占用工具自行退出，目录检查从共享冲突 32 变为 0。本次未强制结束用户工具进程，只清理了独立验证产生的测试进程。

所以准确的结论是：**配置覆盖六项目，一个项目普通入口恢复；没有证据保证所有项目、所有电脑、每次重启和后续版本都已修好。**

## 五、局限和撤销

启动器目前按数字版本读取缓存中最新插件，本机只有一个缓存版本。应用降级、多版本缓存、未来工具策略变化均需重新核对。工具在固定目录解析相对路径，访问项目资料应使用绝对路径。

配置前备份，撤销时只移除本次新增或调整的项，保留随后发生的其他更改。共享信任项的作用是允许这一组项目加载共享配置，范围应限定到副本父目录。完整步骤和验证清单见 [SETUP.md](docs/SETUP.md) 与 [VERIFICATION.md](docs/VERIFICATION.md)。
